## LinkedIn — technical follow-up

Use this later, alongside a simple phone ↔ relay ↔ computer graphic.

```text
A detail behind Shahi: the relay connects your devices, but it doesn’t read the agent conversation.

Your phone and computer both connect outward. Application payloads are encrypted between those endpoints; the relay forwards ciphertext. A one-time QR introduces a device, and each paired device gets its own credential that you can revoke.

The computer keeps herdr, the coding agents and their files. Reader uses the agent’s recorded transcript so the conversation can fit a phone screen. The original terminal remains available on Screen.

There are real boundaries: the relay sees connection metadata, the endpoints and hosted browser code must be trusted, and this has not had an independent security audit. The native iPhone app also supports your own SSH connection.

The code and an illustrated explanation are public:
https://getshahi.dev/
https://github.com/iYassr/shahi/blob/master/docs/connection-security.md
```

## Reddit — open-source / self-hosting audience

**Title:** Shahi: an MIT-licensed phone client for coding agents running in herdr

```text
I’m releasing Shahi, a phone-friendly client for coding agents running inside herdr on your own Mac or Linux computer.

The local sidecar reads the exact agent session’s transcript and exposes a shared API to an iPhone app and a React PWA. You can read the conversation, answer supported approval prompts, browse spaces and send instructions. The computer keeps the agents and files.

The default hosted relay is free. It forwards end-to-end encrypted application payloads, with outbound connections on both sides. It does see connection metadata. You can operate your own relay; the native app also supports SSH to a computer you can already reach. Setting RELAY_URL= disables relay pairing, which also prevents the hosted PWA from connecting to that computer.

There’s no Shahi account. Pairing is through a single-use, ten-minute code, and paired devices can be revoked. A paired device has powerful terminal access, so keep the code private. This has not had an independent security audit.

Stack: Bun sidecar, Cloudflare Worker / Durable Object relay, shared TypeScript encryption and protocol, React PWA, Expo / React Native iPhone app. Source is MIT licensed.

Code: https://github.com/iYassr/shahi
Setup / demo: https://getshahi.dev/
Security explanation: https://github.com/iYassr/shahi/blob/master/docs/connection-security.md

I’m the developer and happy to discuss the boundaries or implementation. I’d welcome practical feedback from anyone running agents on a remote Linux machine.
```

real conversations, home-directory paths, account details and notifications out

### 20-second scroll-stopper

| 3–7s | Open the same question on the phone | “Meet Shahi: your agents, as a chat on your phone.” |
| 7–12s | Read context, tap the supported answer | “Review it. Answer. Keep the same session moving.” |

### 60-second honest walkthrough

1. **0–8s:** Show an agent working in herdr and the phone beside it. Say:
   “Shahi connects to the agents already running on your Mac or Linux computer.”
2. **8–18s:** Show the two setup commands. Cut over the QR scan without exposing
   a real secret. “Once herdr is running: install the plugin, show the code, scan
   it inside Shahi.”
3. **18–35s:** Open an agent, read the latest response and answer a harmless
   supported approval. “Reader follows the conversation; supported questions
   become buttons.”
4. **35–45s:** Send a follow-up, show the response appearing on computer and
   phone. “It is the same session.”
5. **45–52s:** Switch spaces, then Screen. “Browse your work or open the original
   terminal when you need it.”
6. **52–60s:** End card. “The tunnel is included and free. Keep your computer
   awake and connected. iPhone and PWA at getshahi.dev.”

Do not demonstrate destructive commands, automatic approvals, native 1.1.0-only
features or notifications until the deployed build and device acceptance prove
the exact behavior. Avoid sped-up footage that suggests a guaranteed latency.
