# Real-server verification — 18 September 2026

This run uses an iPhone 18 Pro simulator on iOS 27 and a rebuilt browser PWA, connected to an actual Ubuntu machine running herdr 0.9.0. The agent processes and filesystem are real; no fixture responses are used for these checks. Unit tests are separate supporting evidence.

Writes are confined to test workspaces in the named `shahi-e2e-sept18` session. Existing conversations are read-only. The Mac could not reach the relay edge directly, so a loopback WebSocket bridge forwards the unchanged encrypted frames through SSH to the actual Cloudflare relay. This verifies the real relay/server protocol, but not this Mac's direct route to Cloudflare.

## Verified

- Native: QR-code payload pairing, saved-computer switching, relaunch, connection interruption/recovery, temporary-device revocation, pin/unpin, real shell input, computer-file attachment, Read/Screen controls, and a complete Antigravity reply.
- Native creation: 24 UI cases, six installed agents and every offered permission mode from both Agents and Spaces. Each opens its own new conversation. Actual process flags independently checked.
- Web creation: the same 24 UI cases, distinct returned panes and matching process flags independently checked.
- Web: encrypted pairing and remembered connection reload, computer switching, shell input, a complete Antigravity reply, zoom/focus controls, real file upload, computer-file attachment and removal, new space creation, pin/unpin, inbox review dismissal, and device revocation. Both temporary browser grants were revoked; reloading remains unpaired.
- Web layouts: desktop sidebar and phone-width navigation/creation, with no horizontal overflow at 1440 × 1000 and 390 × 844.
- Web reader: actual long Claude and Codex conversations retain the exact reading position after Read/Screen switching and reopening. Loading older history and then selecting Latest reaches the actual bottom.
- PWA: offline reload renders the app shell, reconnecting restores the real conversation automatically, Chrome reports no installability errors, and the inspected service-worker cache contains assets rather than private API/conversation responses.
- Backend: all twelve installed agent/mode combinations, concurrent repeated default names, operation-ID replay protection, and a real Codex menu answer.
- Native long-reader checks from the preceding work on the same actual server verified Claude/Codex history, exact paragraph restoration after navigation or Read/Screen changes, and reaching the final message.

## Fixes from this run

- Repeated agent creation no longer fails because the default internal name is already used. Collision recovery reuses the new pane instead of making another tab.
- Native and web folder pickers discard stale results and show recoverable failures; late picker/upload completions do not change a dismissed conversation.
- Web attachment browsing can return to the home folder when the session's folder is outside the browsable home directory.
- Pending web agent creation cannot be dismissed or submitted twice.
- Device-management requests and confirmations cannot act on a dismissed screen; browser self-revocation explicitly leaves the authenticated view.
- Provider labels, filter icons and speaker colors are consistent across clients.
- Web reader restoration now retains the message anchor, its viewport offset and the loaded history window. Latest targets the scroll container’s actual bottom.
- An offline or temporary pane-loading failure no longer falsely declares the conversation deleted. The view offers retry and recovers when connectivity returns.

## Limits and operational incident

Claude and Codex hit existing provider usage limits; Pi requests authentication. Startup, selected permission flags, delivery and error display are verified, but successful AI work under every permission mode cannot be claimed. Antigravity supplied a genuine successful reply. Push delivery, camera scanning, dictation and physical-device Safari installation remain unverified. Native SSH onboarding was not exercised in this relay-focused run. Browser E2E used Chrome; this report does not claim real-server Safari coverage.

Starting a named herdr session under the usual configuration ran the installed Shahi startup hook and temporarily redirected the main sidecar to the test session, approximately 01:29–01:40 +03. The original connection was restored and verified against 22 original workspaces and 106 panes. The default herdr process was never restarted; test writes targeted the separate test service. Testing instructions now require both a named session and a fresh `XDG_CONFIG_HOME` with no installed plugins.
