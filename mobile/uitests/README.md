# On-device UI checks (XCUITest)

A small `xcodebuild`-driven harness for the things a phone shows and a stub
cannot: real scroll behaviour, on a real transcript, over the relay. It is the
counterpart to `docs/verify-on-device.md` and to the Maestro flows — Maestro can
see that a label is *visible*; XCUITest can read an element's *frame* and drive
precise gestures, which is what a question about *where* you are needs.

It lives outside `mobile/ios/` on purpose: that directory is regenerated by
`expo prebuild`, so a test target added inside it is wiped on the next prebuild.
This project drives the **already-installed** app by bundle id
(`XCUIApplication(bundleIdentifier: "app.shahi.mobile")`), so it needs no host
app and no share of the Expo project.

## Running

Prerequisites: a booted simulator with the app **installed and paired to a box**
(a dev-client on Metro is ideal — a JS change is a reload, not a rebuild), and
at least one agent pane.

```sh
cd mobile/uitests
./run.sh                       # generates the project and runs every test
./run.sh -only-testing:ShahiUITests/ReaderPlaceTests
```

`run.sh` regenerates `ShahiUITests.xcodeproj` with `xcodegen` first — **always
regenerate after adding a `.swift` file**, or the new file is not compiled.

## `ReaderPlaceTests`

Proves reading mode keeps your place: scroll back up a conversation, then
leaving the pane and returning (or glancing at the raw screen and back) must not
throw you to the newest message. The signal is content-independent — the
"Latest ↓" pill is present exactly when you are away from the tail — and the
`MARK nnn` markers let it check you returned to the *same* message.

The negative control is real: setting the reader's `following`/`pendingRestore`
to the at-tail state (disabling `scrollMemory`) fails
`…AcrossLeavingThePane`, which is the load-bearing case. `…AcrossTheScreenToggle`
is held by the overlay design (the list is never unmounted on a toggle), so it
passes with or without the restore; it guards against a regression to unmounting.

### It needs a long conversation

The reader only overflows — and "place" only means something — when the
transcript is longer than the screen. The tests `XCTSkip` when no `MARK nnn`
markers are on screen. To seed a pane's transcript, append numbered
user/assistant rows to its Claude JSONL and re-read:

1. Find the pane's session id: `herdr pane get <paneId> | …agent_session.value`.
2. Its transcript is `~/.claude/projects/<encoded-cwd>/<sessionId>.jsonl`.
3. Append rows whose assistant text contains `MARK 001`, `MARK 002`, … (a few
   lines each, so cells have height). Back the file up first.

This is a **local** device check, not CI: it needs a paired box and a seeded
pane, so it is run by hand the way `docs/verify-on-device.md` is.
